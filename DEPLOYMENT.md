# RKS ONE — Deployment Guide

RKS ONE runs on three hosted services, all deployed from GitHub `rkscomputercenter/rksone` (branch `main`):

| Part | Host | Address | Built from |
|---|---|---|---|
| Web app (React) | Vercel | https://rksone.qenbel.site (https://app.rksone.qenbel.site redirects here) | `frontend/` + `frontend/vercel.json` |
| API (Express + Socket.IO + cron jobs) | Render, Docker, Singapore | https://api.rksone.qenbel.site | root `Dockerfile` + `render.yaml` |
| Database | Supabase, Postgres 17, ap-southeast-1 | session pooler, port 5432 | `backend/prisma/schema.prisma` |

The Android app and the desktop wrapper load the web app and call the API at the same addresses.

```
 Browser / Android app / desktop
        │  pages, version.json            │  /api/*, /api/socket.io (Bearer token)
        ▼                                 ▼
  rksone.qenbel.site (Vercel)     api.rksone.qenbel.site (Render) ──► Supabase Postgres
```

Why the web app has one main address: logins are saved in the browser per address, so two live addresses would log people out whenever they switched. `app.rksone.qenbel.site` is a permanent redirect.

## 1. Supabase

The project exists; the 21 Oct backup was restored as a dry run on 2026-10-25 (see `HANDOFF.md` §6).

- Use the **session pooler** (port 5432) for the API. Prisma prepares statements, which the transaction pooler (6543) does not support without `pgbouncer=true`.
- URL-encode special characters in the password (`@` → `%40`).
- RLS is on for every table with no policies, so Supabase's own REST API exposes nothing. Prisma connects as the owner and is not restricted. Keep it this way.

```
postgresql://postgres.<project-ref>:<password>@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres?sslmode=require&connection_limit=5
```

## 2. Render (API)

1. Render Dashboard → **New → Blueprint** → connect `rkscomputercenter/rksone`. Render reads `render.yaml` and creates `rksone-api`.
2. Enter the secrets it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the URL from step 1 |
   | `JWT_SECRET` | generated by Render automatically (`generateValue`); do nothing. It is new, never the old service's. Changing it logs everyone out. |
   | `APK_URL` | absolute link to the current Android APK (e.g. a GitHub Release asset). APKs are not in git, so neither server can host one. |

   Already set by `render.yaml`: `NODE_ENV=production`, `PORT=10000`, `TZ=Asia/Kolkata`, `LOG_RETENTION_DAYS=60`, `TRUST_PROXY_HOPS=1`, `KEEP_AWAKE=always`, `ALLOWED_ORIGINS=https://rksone.qenbel.site,https://app.rksone.qenbel.site`.
3. **Settings → Custom Domains** → add `api.rksone.qenbel.site`.
4. Check: `curl https://api.rksone.qenbel.site/api/health`.

Render redeploys on pushes to `main` that touch `backend/`, `Dockerfile`, `.dockerignore` or `render.yaml` (`buildFilter`).

On start, `backend/entrypoint.sh` runs `prisma db push` (no data-loss changes without a flag), seeds an `admin` only if the users table is empty, then starts the server.

## 3. Vercel (web app)

1. Vercel → **Add New → Project** → import `rkscomputercenter/rksone`.
2. **Root Directory: `frontend`**. Framework, build command and output come from `frontend/vercel.json`.
3. Environment variables are optional; the defaults in `frontend/src/config.ts` are the production addresses:
   - `VITE_API_ORIGIN` (default `https://api.rksone.qenbel.site`)
   - `VITE_APP_ORIGIN` (default `https://rksone.qenbel.site`)

   For a preview deployment against another API, set `VITE_API_ORIGIN` and add that preview's address to the API's `ALLOWED_ORIGINS`.
4. **Settings → Domains** → add `rksone.qenbel.site` and `app.rksone.qenbel.site`. `vercel.json` redirects `app.` to the main address.

Vercel builds every push to `main` (about 15 seconds).

## 4. DNS (qenbel.site)

| Name | Type | Value |
|---|---|---|
| `rksone` | CNAME | the target Vercel shows for the domain (usually `cname.vercel-dns.com`) |
| `app.rksone` | CNAME | same as above |
| `api.rksone` | CNAME | `rksone-api.onrender.com` (the address Render shows) |

If the DNS host is Cloudflare, keep these records **DNS only (grey cloud)**: Vercel and Render issue their own certificates. If you proxy `api.rksone` through Cloudflare anyway, set `TRUST_PROXY_HOPS=2` on Render.

## 5. CI

`.github/workflows/ci.yml` runs on every push to `main` and on pull requests:
- backend: typecheck, plus the integration tests against a throwaway Postgres 17
- frontend: typecheck and production build

It does not deploy; Render and Vercel deploy `main` through their GitHub integrations.

## 6. Verify after a deploy

```bash
curl https://api.rksone.qenbel.site/api/health
curl -si -X OPTIONS https://api.rksone.qenbel.site/api/auth/login \
  -H 'Origin: https://rksone.qenbel.site' -H 'Access-Control-Request-Method: POST' | grep -i access-control-allow-origin
```
Then open https://rksone.qenbel.site, sign in, and check that the live updates connect. The browser console shows `[SOCKET] Connected to real-time server`.

## Troubleshooting

- **API calls fail with CORS errors:** the page's address is missing from `ALLOWED_ORIGINS` on Render. Write it exactly, scheme included; a trailing slash is tolerated.
- **First request takes ~30 s (the server was asleep):** Render's free tier sleeps after 15 idle minutes. `KEEP_AWAKE=always` makes the server ping its own public URL every 10 minutes, day and night, which keeps it from falling asleep. That cannot wake a server that is already asleep: after a deploy, restart or crash, open `/api/health` once. For a guarantee, use a paid Starter instance (and drop `KEEP_AWAKE`). The nightly jobs (bank totals at 20:00 and 23:59, maintenance at 01:00) only run while the server is awake.
- **Container exits with `Invalid environment configuration`:** `DATABASE_URL` or `JWT_SECRET` (16+ characters) is missing or wrong.
- **Database unreachable:** Supabase free projects pause after 7 days of inactivity. Restore the project in the dashboard, then redeploy.

## Free-tier limits

| Service | Limit |
|---|---|
| Render Free | Sleeps after 15 min idle (cold start ~30 s); 750 h/month |
| Supabase Free | Pauses after 7 days idle; 500 MB; no point-in-time recovery (take scheduled dumps) |
| Vercel Hobby | Non-commercial use only per Vercel's terms. A shop's internal tool may need the Pro plan. |

1. Render first: create the service with the values above, wait until it is live, open `https://<service>.onrender.com/api/health`.

4. Check section 6, then sign in.

## Android app (RKS ONE)

The Android app is the web app bundled into an APK with Capacitor (`com.shoprks.app`). A new web version reaches
phones only as a new APK, so the app has an update manager and a version number.

### How an installed app finds updates
| App | Asks | Downloads from |
|---|---|---|
| **1.0.41 and older** (the Shop RKS in the field) | `https://shop-rks.onrender.com/version.json`, then checks the password against the **old** API | `/Shop_RKS_v1.0.41.apk` on the old server (the file name is fixed in the old server's code) |
| **1.0.42 and newer** (RKS ONE) | `https://rksone.qenbel.site/version.json` | the link from the API (`APK_URL`), after one tap if signed in, or a username and password if not |

The new app's popup shows when `version` in `version.json` is newer than the app. `minVersion` makes it mandatory
(no "Later"); "Later" hides it for 6 hours. It re-checks on start, when the app comes back to the front, and every 2 hours.

### Releasing a new version
1. `cd frontend && npm run version:set -- 1.0.43` sets the version in `package.json`, `public/version.json` and `android/app/build.gradle`
   (`versionCode = major*10000 + minor*100 + patch`; it refuses a number that is not higher: Android will not update otherwise).
2. Write the release notes in `public/version.json`. Do **not** push yet.
3. `npm run build && npx cap sync android`
4. `cd android && gradlew assembleRelease` (JDK 21 from Android Studio: `JAVA_HOME=C:\Program Files\Android\Android Studio\jbr`)
5. `node scripts/package-release.mjs` checks the signature against the installed app and writes `release/`.
6. Upload `release/RKS_ONE.apk` to a GitHub Release (tag `v1.0.43`; the API's `APK_URL` is
   `https://github.com/rkscomputercenter/rksone/releases/latest/download/RKS_ONE.apk`, so it always serves the newest).
7. Only now push `public/version.json`. Phones start offering the update as soon as Vercel serves it.

### Signing
Always the original keystore (`D:\shop-rks\frontend\android\app\release.keystore`, alias `shoprks`), through the gitignored
`android/keystore.properties`. A different key makes Android refuse to install over the existing app. Back the keystore up
somewhere safe: if it is lost, every installed app must be uninstalled and reinstalled by hand.
SHA-256 of the certificate: `D6:BF:D3:D6:5D:3F:8F:F1:13:23:38:97:07:B7:38:73:AF:96:C6:AD:FA:D1:19:39:6E:10:2C:19:2B:BF:34:39`.

### The one-time bridge (moving installed apps from the old server)
`release/old-server/` (made by step 5) holds the two files to put in `D:\shop-rks\frontend\public\` and a README.
